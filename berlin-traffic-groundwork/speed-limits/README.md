What openly serves the **posted / legally ordered speed limit** of a Berlin street
(the *signed* limit — Tempo 30, Tempo 50, …), as opposed to the **measured** speed
the detectors report. This was the open gap flagged in
[`../01-car.md`](../01-car.md): the TEU/ThermiCam feeds and the `vmzlos` Verkehrslage
map all carry *measured* or *free-flow reference* speeds, **none of them the legal limit**.

## Executive summary

- **There is one authoritative open dataset for the *ordered* limits: the Berlin
  Geoportal `Tempolimits` layer**, published by **SenMVKU** as **WFS + WMS**
  (`gdi.berlin.de/services/wfs/tempolimits`, feature type
  `tempolimits:hoechstgeschwindigkeit`). Verified live: **29,800 segments**, geometry
  snapped to the **Detailnetz Berlin** road network, CRS **EPSG:25833**, last revised
  **2025-05-22**, licence **dl-de/zero-2.0** (the most permissive German open licence —
  effectively public domain, no attribution required).
- **It stores only *deviations* from the StVO default of Tempo 50** (plus autobahn 50
  shown explicitly). So it is overwhelmingly the **Tempo-30 network**: of the 29,800
  segments, **28,495 (95.6 %) are `wert_ves = 30`**. A street with no feature ⇒ the
  default 50 applies. Each segment carries the **reason** (`durch_t`: e.g. *Lärmschutz*,
  *Schulwegsicherung*, *Straßenschäden*) and any **time/day restriction** (`zeit_t`/`tag_t`).
- **OpenStreetMap is the practical citywide complement.** Live Overpass (2026-06-02):
  of **87,992** drivable-road ways in Berlin, **83,436 carry an explicit `maxspeed`
  tag — ~94.8 %**, and routing engines infer the rest from defaults + `zone:maxspeed`.
  OSM *does* encode the default 50 and zone limits (which the Geoportal omits), but its
  provenance is mixed and it is **ODbL** (share-alike + attribution).
- **VIZ / DPS does *not* publish a separate live "speed-limit" API.** VIZ is the
  traffic-management umbrella; the canonical static limit data is the **SenMVKU Geoportal
  layer above**, which VIZ surfaces cartographically. The **federal republication path**
  is the **Mobilithek** national access point as **DATEX II** (RTTI *speed-limits* profile)
  — the channel navigation providers consume. *(See the confidence caveat in that file.)*
- **Bottom line / which to use:**
  | If you need… | Use |
  | --- | --- |
  | The *authoritative ordered* limit + legal reason + Detailnetz linkage, no-attribution licence | **Geoportal `Tempolimits` WFS** |
  | A *complete* per-way limit incl. the default-50 streets, ready for routing | **OSM `maxspeed`** (ODbL) |
  | A *standardised national* feed for a navigation/ITS stack | **Mobilithek DATEX II** |
  | *Measured* speed (not the legal limit) | TEU/ThermiCam or `vmzlos` — see [`../01-car.md`](../01-car.md) |

## Key insight

The legal-speed-limit gap is **filled, but split**: the **Geoportal `Tempolimits`** layer
is the *authoritative, legally-grounded* source (with the ordering reason and the most
permissive licence) — but by design it is **just the exceptions to Tempo 50**, so on its
own it cannot tell you the limit of an arbitrary street, only whether one *deviates*. **OSM
`maxspeed`** is the only source that resolves to a limit for **every** drivable way (explicit
tag for ~95 %, defaults/zones for the rest) and is what routing actually runs on — at the
cost of mixed provenance and ODbL share-alike. The clean pattern is to **treat the Geoportal
layer as ground truth for the ordered limits and OSM as the citywide fill** (and, if you need
a standardised machine feed for an ITS/navigation stack, take it from **Mobilithek DATEX II**).
